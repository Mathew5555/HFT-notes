# PyTorch: от данных до обученной модели

**PyTorch** — библиотека для работы с тензорами и обучения моделей. Мы задаём вычисления и функцию потерь; библиотека автоматически вычисляет производные, а оптимизатор обновляет параметры.

Разберём весь процесс на простой задаче: **по двум числам предсказать их сумму**. Правило известно заранее, поэтому легко проверить, чему научилась модель.

```text
Данные → train / validation / test → батчи → модель
                                            ↓
                                  предсказание → loss
                                            ↓
                                  градиенты → обновление весов
```

## Как запустить пример

Создай файл `pytorch_basics.py` и **скопируй в него Python-блоки ниже по порядку**, до раздела «Что потестировать». Вместе они образуют один исполняемый пример. Достаточно установленного `torch`; скачивать датасеты не нужно.

В терминале из папки с файлом, в активированном окружении:

```bash
python pytorch_basics.py
```

Пример работает на CPU. Рядом с файлом появится `sum_model.pt` — параметры лучшей по validation модели.

## Данные: что получает модель

**Тензор** — многомерный массив чисел. Для табличных данных обычно каждая строка соответствует объекту, каждый столбец — признаку.

```python
from pathlib import Path

import torch
from torch import nn
from torch.utils.data import TensorDataset, DataLoader, random_split

torch.manual_seed(42)

X = torch.rand(1000, 2)                 # 1000 объектов, 2 признака
y = X.sum(dim=1, keepdim=True)          # один ответ на объект

print("X:", X.shape, X.dtype)           # [1000, 2], float32
print("y:", y.shape, y.dtype)           # [1000, 1], float32
print("Пример:", X[0], "→", y[0])
```

Например, признаки `[0.2, 0.7]` соответствуют ответу `[0.9]`. `dim=1` означает суммирование по столбцам каждой строки. `keepdim=True` сохраняет размерность: ответ имеет форму `[1000, 1]`, а не `[1000]`.

**Размерности важны:** предсказание и ответ для этой задачи должны иметь одинаковую форму. Иначе автоматическое расширение размерностей — **broadcasting** — может привести к вычислению совсем другой ошибки.

На практике `X` и `y` получают из таблиц, изображений или последовательностей. Например, массив NumPy переводят в тензор через `torch.as_tensor(array, dtype=torch.float32)`. Само преобразование не нормирует признаки.

## Dataset: связываем признаки и ответы

**Dataset** задаёт, как получить один объект и его ответ. Если данные уже находятся в тензорах, подходит `TensorDataset`:

```python
dataset = TensorDataset(X, y)
features, target = dataset[0]
print("Объект из Dataset:", features, target)
```

`dataset[i]` возвращает пару `(X[i], y[i])`. Перемешивание объектов в дальнейшем не нарушит соответствие признаков и ответов.

Если данные лежат в отдельных файлах, можно написать свой класс `Dataset` с методами `__len__` и `__getitem__`: первый возвращает число объектов, второй загружает объект по индексу. **Transforms** — преобразования при подготовке объекта, например перевод изображения в тензор или нормировка.

## Разделение данных

```python
train_data, val_data, test_data = random_split(
    dataset,
    [700, 150, 150],
    generator=torch.Generator().manual_seed(42),
)
```

| Часть | Для чего используем |
|---|---|
| **Train** | Вычисляем градиенты и обновляем параметры |
| **Validation** | Выбираем гиперпараметры, архитектуру и лучшую эпоху |
| **Test** | Один раз оцениваем выбранную итоговую модель |

Здесь объекты независимы, поэтому подходит случайное разделение. Временные ряды обычно разделяют по времени: обучение на прошлом, проверка на последующих периодах. Параметры предобработки, например среднее и стандартное отклонение, вычисляют **только по train**.

`manual_seed` фиксирует исходное состояние генератора случайных чисел. Это помогает повторять эксперимент в одинаковых условиях, но не гарантирует полное совпадение на разном оборудовании.

## DataLoader: получаем батчи

**DataLoader** собирает отдельные объекты из Dataset в **батчи** — группы для совместной обработки.

```python
train_loader = DataLoader(train_data, batch_size=32, shuffle=True)
val_loader = DataLoader(val_data, batch_size=32)
test_loader = DataLoader(test_data, batch_size=32)

X_batch, y_batch = next(iter(train_loader))
print("Батч:", X_batch.shape, y_batch.shape)  # [32, 2], [32, 1]
print("Батчей за эпоху:", len(train_loader))  # 22
```

Из 700 объектов получатся 21 батч по 32 и последний из 28. По умолчанию неполный батч сохраняется.

- **Батч** — группа объектов для одного шага обучения в нашем примере.
- **Шаг обучения** — вычисление ошибки, градиентов и обновление параметров.
- **Эпоха** — полный проход по обучающей выборке: здесь 22 шага.

`shuffle=True` перемешивает порядок train при каждом новом проходе по загрузчику. Для validation и test перемешивание обычно не требуется.

## Как создаём и выбираем модель

PyTorch не выбирает модель за нас. Архитектуру задаём сами, а её пригодность оцениваем на validation.

Для суммы достаточно **линейной модели**:

```text
ŷ = w₁x₁ + w₂x₂ + b
```

Правильное решение: `w₁ = 1`, `w₂ = 1`, `b = 0`. При создании слоя параметры инициализируются случайно; модель должна найти их в процессе обучения.

```python
class SumModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.linear = nn.Linear(in_features=2, out_features=1)

    def forward(self, x):
        return self.linear(x)


model = SumModel()
print(model)
print("Форма предсказания:", model(X_batch).shape)  # [32, 1]
```

- `nn.Module` — базовый класс моделей и слоёв.
- `__init__` — создаёт слои и регистрирует их параметры.
- `forward` — описывает вычисление предсказания.
- `model(X_batch)` — запускает эти вычисления. Обычно вызывают именно модель, а не `forward` напрямую.

`nn.Linear(2, 1)` принимает последнюю размерность длины `2` и заменяет её на `1`. В нашем случае у него три обучаемых параметра: два веса и сдвиг.

### Что зависит от задачи

| Задача | Выход модели | Типичный loss |
|---|---|---|
| Регрессия одного числа | `[B, 1]`, вещественное число | `nn.MSELoss()` или `nn.L1Loss()` |
| Бинарная классификация | `[B, 1]`, один логит | `nn.BCEWithLogitsLoss()` |
| Классификация на `C` классов | `[B, C]`, логит каждого класса | `nn.CrossEntropyLoss()` |

`B` — размер батча. **Логит** — исходное число до преобразования в вероятность. Для бинарного loss таргеты имеют ту же форму, что и логиты, и вещественный тип. Для указанного многоклассового случая таргеты — номера классов формы `[B]`, тип `torch.long`.

Перед `BCEWithLogitsLoss` не добавляют sigmoid, а перед `CrossEntropyLoss` — softmax: нужные преобразования уже входят в вычисление loss. Для получения вероятностей при применении модели используют sigmoid или softmax соответственно.

## Loss, градиенты и оптимизатор

**Loss** измеряет ошибку. **Оптимизатор** получает параметры модели и обновляет их по градиентам.

```python
loss_fn = nn.MSELoss()
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
```

Здесь MSE — средний квадрат разницы предсказания и ответа, `lr` — **learning rate**. В `model.parameters()` находятся обучаемые параметры зарегистрированных слоёв.

Один шаг обучения выглядит так:

```text
optimizer.zero_grad()       → очищаем старые градиенты
prediction = model(X_batch) → получаем предсказания
loss = loss_fn(prediction, y_batch) → измеряем ошибку
loss.backward()             → вычисляем градиенты параметров
optimizer.step()            → обновляем параметры
```

При прямом проходе PyTorch строит граф вычислений. `backward()` проходит по нему в обратном направлении и по цепному правилу вычисляет производные. Результат записывается в `.grad` параметров.

**`backward()` не обновляет веса**, а `step()` не вычисляет производные. Без `zero_grad()` новые градиенты прибавятся к старым.

## Обучение и проверка

Сначала определим функцию оценки на всей выборке:

```python
@torch.no_grad()
def evaluate(model, loader):
    model.eval()
    total_loss = 0.0
    total_objects = 0

    for features, target in loader:
        prediction = model(features)
        loss = loss_fn(prediction, target)
        total_loss += loss.item() * len(features)
        total_objects += len(features)

    return total_loss / total_objects
```

`loss.item()` извлекает число из скалярного тензора. MSE здесь усредняется внутри батча, поэтому умножаем его на число объектов и делим общую сумму на размер выборки. Так последний неполный батч получает правильный вес.

**Режим модели и вычисление градиентов — разные настройки:**

| Команда | Что делает |
|---|---|
| `model.train()` | Включает обучающее поведение слоёв, например Dropout и BatchNorm |
| `model.eval()` | Переключает такие слои в режим применения |
| `torch.no_grad()` | Отключает построение графа для вычисления градиентов |

`eval()` сам по себе не отключает градиенты. В нашей линейной модели режимы дают одинаковое вычисление, но привычка явно переключать их важна для более сложных сетей.

Теперь обучим модель. После каждой эпохи проверяем validation; при улучшении сохраняем параметры.

```python
model_path = Path(__file__).resolve().parent / "sum_model.pt"
best_val_loss = float("inf")

for epoch in range(1, 41):
    model.train()
    total_loss = 0.0
    total_objects = 0

    for features, target in train_loader:
        optimizer.zero_grad()
        prediction = model(features)
        loss = loss_fn(prediction, target)
        loss.backward()
        optimizer.step()

        total_loss += loss.item() * len(features)
        total_objects += len(features)

    train_loss = total_loss / total_objects
    val_loss = evaluate(model, val_loader)

    if val_loss < best_val_loss:
        best_val_loss = val_loss
        torch.save(model.state_dict(), model_path)

    if epoch == 1 or epoch % 10 == 0:
        print(f"Эпоха {epoch:2d}: train={train_loss:.6f}, val={val_loss:.6f}")
```

**Ожидаем:** train и validation MSE уменьшаются к нулю. Если train улучшается, а validation устойчиво ухудшается, это признак переобучения. В простой задаче сложение должно хорошо восстанавливаться линейной моделью.

Обучающая ошибка здесь собирается по мере обновления весов, а validation считается с параметрами в конце эпохи. Поэтому это не две оценки одной и той же фиксированной модели.

## Загружаем модель и получаем ответ

**`state_dict()`** — словарь весов и другого сохраняемого состояния слоёв. Он не содержит код архитектуры: перед загрузкой нужно создать такую же модель.

```python
loaded_model = SumModel()
state = torch.load(model_path, map_location="cpu", weights_only=True)
loaded_model.load_state_dict(state)
loaded_model.eval()

print("Test MSE:", evaluate(loaded_model, test_loader))

new_X = torch.tensor([[0.2, 0.7], [0.4, 0.1]], dtype=torch.float32)
with torch.no_grad():
    prediction = loaded_model(new_X)

print("Предсказания:", prediction.squeeze(1))  # около [0.9, 0.5]
print("Веса:", loaded_model.linear.weight.detach())  # около [[1, 1]]
print("Сдвиг:", loaded_model.linear.bias.detach())   # около [0]
```

Test используем после выбора лучшей по validation эпохи. Для нового предсказания правильные ответы не нужны — достаточно признаков в том же формате и с той же предобработкой, что при обучении.

`map_location="cpu"` загружает тензоры на CPU; `weights_only=True` ограничивает загрузку данными, поддерживаемыми этим режимом. `detach()` возвращает тензор, отсоединённый от графа вычислений.

Для **продолжения обучения** обычно сохраняют checkpoint: состояние модели, оптимизатора и номер эпохи. Например, Adam хранит накопленные оценки градиентов; одних весов недостаточно для восстановления его состояния. Для применения модели достаточно весов, определения архитектуры и сохранённых настроек предобработки.

## Что потестировать

Меняй по одному параметру и смотри на результат:

| Изменение | На что смотреть |
|---|---|
| `batch_size=1`, `32`, `700` | Размер батча и число обновлений за эпоху |
| Одна эпоха вместо 40 | Веса ещё могут заметно отличаться от `[1, 1]` |
| `lr=0.001` вместо `0.1` | Обучение за то же число эпох обычно идёт медленнее |
| Убрать `optimizer.step()` | Параметры останутся прежними, ошибка не будет снижаться за счёт обучения |
| Вывести `model.linear.weight.grad` после `backward()` | Производная loss по каждому весу |
| Заменить `y` на `2 * X[:, :1] - X[:, 1:] + 0.5` | Новые ожидаемые веса `[2, -1]`, сдвиг `0.5` |

Чтобы попробовать нелинейную сеть, замени `self.linear` в `__init__` на:

```python
self.linear = nn.Sequential(
    nn.Linear(2, 16),
    nn.ReLU(),
    nn.Linear(16, 1),
)
```

Остальной цикл обучения останется прежним. Убери только два финальных вывода `.weight` и `.bias`: теперь `self.linear` — последовательность слоёв. Для линейного правила такая сеть избыточна; сравни её с исходной на validation.

## Как перенести пример на свои данные

1. Подготовить признаки и таргет с понятными размерностями и типами.
2. Разделить данные и обучить предобработку только на train.
3. Создать Dataset и загрузчики батчей.
4. Выбрать архитектуру, выход и loss под задачу.
5. Обучать на train, выбирать настройки по validation.
6. Оценить итоговую модель на test и сохранить веса вместе с нужными настройками.

Для работы на GPU модель и входные тензоры должны находиться на одном устройстве. Модель переносят через `model.to(device)` **до создания оптимизатора**, батчи — через `features.to(device)` и `target.to(device)` в обучении и проверке. Сам выбор устройства не меняет общую схему обучения.
